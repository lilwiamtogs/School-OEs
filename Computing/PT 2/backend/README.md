# Custom form bridge

The site now uses a branded form and sends its answers to the existing Google Form response store. The Apps Script bridge runs as the form owner; anyone who can reach the deployed web app can submit a report.

## One-time setup

1. Open the Google Form in edit mode. Copy the ID from the URL between `/forms/d/` and `/edit`.
2. In `Code.gs`, replace `PASTE_FORM_ID_FROM_EDIT_URL_HERE` assigned to `LF_BRIDGE_FORM_ID` with that ID.
3. Create a standalone Apps Script project at <https://script.google.com>, paste in `Code.gs`, and save.
4. Run `prepareCustomFormBridge` once from the Apps Script editor. Review and grant the Forms, Drive, Sheets, and email permissions. This adds an optional `Photo URL (custom upload)` question to the form if it is not already there, creates the photo folder, and creates the private claims spreadsheet.
5. In Apps Script choose **Deploy → New deployment → Web app**. Set **Execute as** to your account. Set access to the broadest audience permitted by your school that includes the students who will submit (typically anyone). Deploy and authorize.
6. Copy the deployed URL ending in `/exec` into `LOST_FOUND_SUBMIT_URL` in the site's `js/form-config.js`. Keep the existing public CSV URL for the reports feed.
7. Publish the linked response sheet's public board tab as CSV. Make sure it includes the new `Photo URL (custom upload)` field while excluding the contact field. The published CSV URL should point to that public-safe board tab.

To hide an item after a successful handoff, set that row's `Status` value to `claimed` in the public-safe board tab. Leave active rows blank or set them to `unclaimed`. Do not edit the published CSV URL or the claims sheet. If the board tab is generated by a formula, add the status column to the source data or update the formula so the status values remain in the published output. If every row is marked `claimed`, the site will correctly show an empty board.

The bridge can also handle approval links in the poster email. Keep `LF_BRIDGE_STATUS_SHEET_ID` set to `USE_FORM_DESTINATION` so status is written to the linked form response sheet, not to a formula-driven public board tab. Set `LF_BRIDGE_STATUS_TAB_NAME` to the response tab name and make sure the public-board formula includes its `Status` column. After redeploying, the poster can approve or decline a claim from the email. Approval marks the matching source row as `claimed`, which the public board can filter, and emails the claimant's contact details to the poster. The claims sheet stays private.

The bridge expects these exact Google Form question titles and types: `Report type` (multiple choice with Lost and Found options), `Item name` (short answer), `Date lost or found` (date), `Last seen or found location` (short answer), `Identifying details` (paragraph), and `Contact email or phone number` (short answer). Make the contact question optional in Google Forms so the site can accept either email or phone without Google's email-only validation. Remove any native File upload question or make it optional; the website uploads photos to Drive itself and writes the link into `Photo URL (custom upload)`. Any other unrelated required questions must also be optional, since the custom form does not answer them. The site performs its own required field validation.

Photos are resized in the browser, saved in Drive, and their links are written into the Google Form response. The submitter must opt in because the photo can be shown on the public report board. School Workspace settings may prevent public Drive links; if so, omit photo submission or use an access policy that permits board visitors to view those images.
